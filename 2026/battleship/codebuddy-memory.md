# CodeBuddy memory

## Project

`battleship`

## Current reality

This folder is the first real proving ground for CodeBuddy.

The immediate goal is to stand up a useful coaching loop that can help shape CodeBuddy itself and then keep nudging weekend work forward.

## MVP

CodeBuddy v0 is done when:

1. there is a real user-level custom agent named `CodeBuddy`,
2. `/checkin` works as a repeatable check-in prompt,
3. CodeBuddy reads these local notes before advising,
4. CodeBuddy can inspect recent repo work and suggest the next MVP-moving step,
5. the setup feels useful enough to iterate on instead of redesigning from scratch.

## MLP

Make check-ins feel supportive, grounded, and specific enough that using CodeBuddy becomes part of the normal weekend workflow.

## Current priorities

1. Finish the first-pass CodeBuddy repo and live ULCA files.
2. Use CodeBuddy to review its own setup and suggest the next iteration.
3. Tighten the project notes format only if that clearly improves future check-ins.

## Success signs

- You can honestly say you made a real agent of your own.
- A check-in response points to a concrete next step instead of generic advice.
- The project notes in this folder stay short enough to maintain.
